# 手绘艺术风格构建指南

这份指南把多轮人工审核中反复出现的问题收束成可执行方法。目标是把同样的美术与交互质量用于编辑器、仪表盘、表单、文件管理、导航或叙事场景，而不是再做一次蘑菇、棋盘和庭院。

这是当前风格要求的主文档。[审核记录](REVIEW_HISTORY.md) 解释规则为何形成；[源码研究](REFERENCE_STUDY.md) 给出机制与数据；[实现指南](IMPLEMENTATION.md) 给出可用工具。源码中的某个时长、弹簧或颜色是样本，不是所有对象都必须照搬的常数。

## 1. 同时看画面与源码，先学关系

参考的完成度来自绘制、结构与动作的配合。只看截图，会误把“米色纸 + 淡色 + 歪边 + 可爱字体”当成风格；只跑代码，会误把有限矩阵、状态成功与帧率当成美术质量。本仓库已经在这两种做法上反复失败。

开始一个功能前完成研究表：

| 要理解的问题       | 必须找到的证据                                   | 转到新项目时写下什么                             |
| ------------------ | ------------------------------------------------ | ------------------------------------------------ |
| 线为何像笔画       | 轮廓变体、笔压、时间图、pivot 与纹理数据         | 哪些线稳定，哪些低频重绘；填色方向与留白怎样安排 |
| 动作为何自然       | clip 通道、idle mask、层混合、anchor、弹簧与事件 | 主体动作、连接部件、接触点、余韵及打断策略       |
| 色彩为何柔和而鲜明 | 纸色、压力色阶、图集真实有色像素                 | 底纸、主颜料、亮面、阴面、轮廓与语义强调色       |
| 控件为何属于画面   | 图标复杂度、hover、文字写擦、on/off 保留状态     | 目标功能的简笔符号、状态痕迹、键盘与点击语义     |

交付时能用具体源码解释动作。例如原作帽子跟随身体倾斜历史、落地时受 jolt、锚点随身体姿态变化；新项目的吊牌便可以沿挂点旋转、跟随纸片加速度、放回时短暂回摆。单独给吊牌一个无关的 `sin(time)` 不算理解了机制。

先画一个完成度足够的主体和一段可反复操作的动作，再扩成整页。局部像草图或动作仍割裂时，增加页面数量不能补救。

## 2. 手绘是精细绘制与媒介感

主体要有清晰的轮廓设计、内部结构、表面方向、厚度与局部个性。线条弯曲、压力不匀、蜡笔缺口是认真绘制之后保留的材料特征，不是降低造型水平的理由。

把一个对象拆成五层，在 2–4 倍局部视图和最终显示尺寸都检查：

1. **形体**：轮廓起伏有意图，转折服从结构。圆润活物、硬纸角、木件不能使用同一粗糙轮廓。
2. **体积**：亮面、侧面、遮挡、底座与接触影说明厚度。无需写实光照，但不能把所有主体画成平面图标。
3. **颜料**：底纸、薄底色、方向性短笔、重叠涂色与阴面分开；留白是笔触之间的空隙。
4. **结构线**：叶脉、羽片、木纹、接缝、刻度、纸边说明对象是什么；不能随机撒点替代结构。
5. **少量个性**：贴片、折角、绑绳、扣件、磨损或附件。细节服从功能与轮廓，避免全屏同等繁密。

一个 SaaS 文件夹可以有纸板侧厚、折痕深色、磨损纸边和手写标签；图表要有认真设计的线条、标记与图例。它们不需要长眼睛或戴帽子。

**失败信号**：放大后只有圆/矩形和一条外线；填色像透明色块；边缘随机锯齿；主要对象与 option 图标一样简略。

## 3. 柔和的纸，大胆且分层的颜料

参考纸色为 `#f1ebde`。局部测量中蓝方角色有 `76,81,144` 等明显深于纸色的有色簇，平均有色像素 alpha 接近 1；文字重笔也有很深的暖红、蓝紫与棕色。柔和主要来自暖纸、局部留白与浓淡变化，不能让整图统一低透明度。[测量范围与数据](REFERENCE_STUDY.md) 不是完整原作色库。

先建立以下颜色角色，而非只选一组浅粉、浅蓝、浅绿：

| 颜色角色   | 用法                           | 当前样本                       |
| ---------- | ------------------------------ | ------------------------------ |
| 底纸       | 页面与对象自身纸底协调         | `#f1ebde`                      |
| 中性笔     | 文字、细节、结构线             | `#725239`                      |
| 主颜料     | 关键对象可从背景中读出         | 蓝紫 `#4c5190`、红棕 `#aa493b` |
| 同材质阴面 | 增强体积，不靠黑框             | 叶片 `#587644`、木纹 `#916b3d` |
| 浅笔与纸隙 | 内部浓淡，而非对象整体褪色     | 由笔压/覆盖密度产生            |
| 功能强调   | 选中、错误、成功，配符号与文字 | 从项目颜料中选，保持语义一致   |

轮廓用对象同颜料的深色，或混入少量暖棕。当前 `pigmentEdge` 是一种实现，不是唯一公式。避免统一纯黑、统一灰细线，也避免所有外缘同样淡。

蜡笔填色采用固定种子的方向性短线，局部重笔可以深；结构之间允许不完整覆盖。实体对象需要自己的不透明纸底，再叠颜料，防止背景/后方部件穿透纸隙。玻璃、水、烟与影子按材料单独处理，不能套纸底。

同时看彩色画面、灰度层次、背景附近边缘及正常尺寸的可读性。不要配色完成后再给整页乘 `.3` 透明度。高密度 SaaS 的数值、错误和键盘焦点仍须清楚，低对比度不会因为“艺术风格”而合格。

## 4. 稳定纹理、轮廓重绘、连续运动各自独立

原地轮廓微微闪烁是参考最明显的生命感之一。正确关系是：

```text
固定种子生成媒介纹理 → 少量预绘轮廓稿低频切换
                       + 连续的位置、目光、姿态和附件求解
```

当前三稿以约 8 Hz 的 `0 → 1 → 2 → 1` 循环，保持支点与主体比例，改变细微曲线。运动仍每帧更新。这是起点；新物件按显示大小和性质调整，不能把 8 Hz 当成所有元素的强制规范。

不应发生：每帧重新掷骰子、对象中心抖动、填色闪噪、所有墙线和文字一直晃、运动也降低到轮廓帧率。文字、精确图表读数与稳定结构通常保持静稿；需要生命感的局部才重绘。减少动作模式固定笔稿，功能继续工作。

先用固定画稿确认对象精美，再打开 boil 比较。若关闭 boil 就不好看，问题在画稿而非动画不足。

## 5. 写出来、擦掉、重新画，必须看见真实过程

**手写文字**由实际书写路径组成，带稳定的字高、倾斜、基线与间距差异；按路径长度逐笔进入。字体外轮廓描边、整行旋转或逐字符透明度不能代替笔迹。字库必须匹配语言：当前原创字库支持拉丁小写、数字与部分标点；中文需要设计中文笔画或合法取得时间图，不能冒称已支持。

**Hover 说明**在指向和键盘聚焦时写出，离开时反向擦除；快速进出从当前墨量衔接，同一标签种子不变。常驻状态保留，不能只在 hover 时才知道声音开关或任务是否完成。

**首次加载**按实际绘制顺序进入：主轮廓、局部色笔、结构细节、说明。可以从真实绘画调用烘焙时间图，播放时推进阈值；不是全图淡入、矩形擦罩，也不是一张完整插画上滚一支假的笔。

**对象替换**先擦掉可见旧笔迹，再绘制新笔迹；打断保存当前进度与对象身份，不能两张半透明对象重叠。Gallery 的角色切换是样本。SaaS 可用于切换小插画、重画空状态或修订图例，不要求业务表格也缓慢擦写。

书写是显示包络，业务状态独立推进。保存、删除、搜索、提交不能等装饰动画结束才执行。长列表、首屏核心任务与高频输入应短促、可跳过；不要照搬场景的 4.8 秒开场到工作软件。

## 6. 自然动作来自结构、阶段与因果

角色与物件都从物性出发。参考蘑菇有蓄力和跳跃，马有头、耳、鬃毛与尾巴的分段响应，猫头鹰左右脚交替，鲸鱼非线性推进。把所有对象换成同一种上下弹跳，即使画稿精细也会割裂。

先画关键阶段，明确主次：

| 阶段      | 要回答的问题           | 无角色的 UI 例子         |
| --------- | ---------------------- | ------------------------ |
| 察觉      | 当前指向什么？         | 纸页角略抬，说明开始写   |
| 预备      | 对象将做什么？         | 拖拽时挂点拉紧，纸边先弯 |
| 主动作    | 功能实际发生在哪？     | 文件纸片移到新位置       |
| 接触/确认 | 到达或状态成立的瞬间？ | 放下纸片，勾画完成       |
| 余韵      | 哪个连接部件稍晚知道？ | 吊牌短摆、擦屑消散       |
| 安静      | 最终状态如何持续可读？ | 新顺序稳定，完成标记保留 |

不是每个控件都要六段长动画。保留阶段关系，时长按功能选择。

- **一套姿态**：身体/纸面、锚点、子件和实际绘制读取共同模型。不要主体一段 tween，饰物再按独立 timer 演出。
- **不同合成规则**：平移/倾斜可累加，尺度/透明度可相乘，表情/画稿需带权选择；不能所有字段都普通插值。
- **连接处决定动作**：铃沿吊点摆、灯罩跟随灯杆、纸角沿折线弯、耳朵跟随头部。附件弹簧由父件变化或接触驱动，角度与能量有界。
- **位移和接触共用相位**：兔子主要在腾空阶段推进，双脚落地一次；猫头鹰左右脚交替。拖动卡片的放下事件必须与实际到达一致。
- **停止/反向不重置**：保存当前姿态、位置、速度、抬升与墨量。参考 timeline 的 ghost 保存中断样本再淡出，新动作由此进入。
- **Idle 有原因与节制**：呼吸、眨眼、目光和偶发小动作分别管理；只对需要活感的对象启用，不让整个仪表盘不停摇晃。

睡眠抽动来自画稿相对角度补偿符号错误；长凳瞬移来自不可达路线被当作到达、中断时丢失抬升。只看 clip 数值连续不足以验收，必须检查最终画稿端点和屏幕上的完整 pose。

## 7. Options 是简笔符号，主体才是精细插画

参考主体很细，选项却经济：星星、Z、扬声器、箭头和短笔迹。把选项画成复杂场景小插画会混淆层级，这是明确的人工纠正。

为新功能只画必要的几笔、有限颜色和一个轻微局部响应。开关用保留的划线、波纹、填星、点或位置表达状态；hover 可改变符号姿态并写说明。避免白底矩形、黑框、标准 tooltip 与普通 navbar 突然插入纸笔世界。

组件仍须是可用的按钮、链接、复选框或输入框。绘图负责外观，语义控件负责键盘、焦点、名称、禁用与状态；同一功能在不同页面采用一致的符号和书写行为。

SaaS 转译：搜索是短笔放大镜，完成是逐笔勾，撤销是弯箭头，收藏是星，静音是扬声器与擦写的波纹。上传/保存的过程表达实际进度和结果，不插入与业务无关的角色表演。

## 8. 空间、布局、文字与输入属于同一张纸

场景先统一地面投影与竖直方向，再用同一基向量画平台、房屋、画栏、凳子、灯与盆栽。接触影贴地，落点/碰撞用世界坐标，深度排序服从实际位置。长凳有靠近、抬升、坐定、下来与重新走动的衔接，不穿过凳子。

普通 SaaS 不必采用斜投影。可用分层纸面、折角、侧厚、局部接触影与克制遮挡表达空间；数据布局仍按阅读顺序组织。对象有体积不等于整页必须成为 RPG 小镇。

标题、说明与控制区需要专门留白。用实际笔迹宽度和上下界测量，不只看 DOM 字框。Gallery 曾把标题与画栏说明挤在同一天际线，也让角色挡住说明；应扩大空间、保留文字区域，必要时将功能标签作前景层绘制。

纸面随指针轻晃时，视觉和语义控件共用变换，命中使用逆变换。不能只让 Canvas 晃、按钮留在旧坐标。离开后回稳，减少动作时停晃。窄屏重新安排构图和点击区，不靠整体缩小让字不可读。

## 9. 小交互、声音与残留服务真实功能

环境元素可以被轻轻探索：拉灯绳改变灯光，点水面起波纹，浇水使植物回应，坐凳进入休息。这些是对象做自己的事情，不是每个东西统一爆星星。

SaaS 中可以划掉已完成事项、拖纸片重排、圈选图表范围、给收藏填星、修订便笺时擦旧写新。去掉角色以后，功能、美术和状态仍应成立。

残留绑定真实事件：落脚留痕、放下有短接触影、擦字有少量擦屑；每个残留有出生时间、衰减与数量上限。不能整条轨迹同时消失，也不能十次操作后堆满碎屑。

声音绑定接触与笔迹进度，画面和声音由同一事件源触发。纸是摩擦，木材是短接触，铃有金属衰减；不能所有 click 都用电子提示音。Hover 不必发声。写擦只在发生时轻响，静音立即停止已有尾音，隐藏和卸载要清理。AudioContext 成功或频谱测试只证明算法工作，舒适度要真实试听。

文案只说明功能、对象或状态，删除无意义的 slogan。产品语言先统一；字库不完整时补字或使用可读正文，不混入无法呈现的装饰语。

## 10. 从零构建的顺序与验收

1. **功能与美术分镜**：定义用户任务、状态、材质、主次和关键动作阶段。列出不会被角色代替的业务内容。
2. **源码研究**：读关联机制，画数据流，说明借鉴关系与自行实现部分。未取得的绘图生成器不作假设。
3. **局部画稿**：完成一个主体、一种简笔选项和一行笔迹；正常和放大尺寸都审查细节、色彩与体积。
4. **真实交互**：接到状态模型，实现写擦、主动作、连接件、接触和余韵，并支持打断。
5. **布局扩展**：保留留白、统一层级与导航，扩到其它功能。不同对象重新调动作，不复制同一弹簧参数。
6. **反复操作**：慢动作、正常速度、连续十次、快速反向、中断、静置、键盘、窄屏、静音与减少动作分别验证。

完成前回答：

- 主体是否精细且有结构，关闭动画仍好看？
- 颜料是否柔和而有分量，纸隙保留，边缘从背景中读得出？
- boil 是否局部稳定，运动和文字仍流畅可读？
- 开场/说明/替换是否沿真实笔迹绘制和擦除，半途反向是否连续？
- 每个动作能否解释源码关系、物性、连接处、接触与收尾？
- 选项是否简练，状态持续可读，导航一致？
- 透视、点击、遮挡与文字空间是否正确，业务操作确实发生？
- 去掉角色、棋盘和庭院之后，这套方法是否仍服务目标产品？

若失败，不用增加装饰、文案或测试数量来补充完成感。修正对应画稿、模型或机制，再扩展。
