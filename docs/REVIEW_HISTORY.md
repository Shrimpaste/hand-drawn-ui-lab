## 最关键的重复失败

### 只学视觉气质，没有学对象完成度

第一次原创把暖纸、细线和淡色当核心，却忽略内部结构、笔压、蜡笔缺口、部件厚度。纠正后才建立局部放大检查与完整主体画稿。后来又出现过淡的颜色；真实图集颜色簇说明“舒服”并不要求浅到贴进背景。

可迁移到 SaaS：先把文件、图表、输入区域、导航符号认真设计，不靠背景和字体承担全部手绘感。

### 动画看起来在动，但结构是错的

旧角色各件有独立波形，没有共同 anchor、父子关系或中断样本。后来直接学求解器依然有适配错误：睡眠曲线连续，切画稿角度却跳；坐凳模型坐标有限，完整画面却瞬移。

可迁移规则：追踪“业务模型 → pose → rig/锚点 → 画稿 → 最终矩阵”。对真正参与绘制的端点检查，不能只对 clip 参数或模型 x/y 做有限数检查。泛化到卡片、吊牌、折页、图表标记同样成立。

### 把详细插画和简单选项混在一层

选项一度做得过于丰富，反而像场景主体；旧导航是文字链接，另一个入口是新插画，语言分裂。人工明确要求参考选项的简笔 Z、星、箭头、扬声器，以及 hover 说明真实写擦。

可迁移规则：复杂度有等级。场景与主要内容精细；高频 options 用几笔清楚表达，状态常驻可读，跨页统一。

### 功能与“氛围”脱节

旧版声音像电子通知，文字像模板 slogan，画廊像三张卡片。后续让对象做自己的事情：走近观察、灯开关、水波、浇水、坐下。没有明确功能的诗句清理，不能把质量差的阁楼长期当成“还待细化”。

可迁移规则：功能本身可以被画出来、圈起来、划掉、归档。产品不必游戏化，但装饰必须有原因，艺术表达不能妨碍业务。

### 轮廓在动，整张画却没有重画（2026-10-06）

人工审核指出原创场景虽然视觉符合，但生命感仍弱：reference 的主体和交互元素在多个不同画面间交替，不能只改轮廓。此前三稿使用同一填色/内部结构，错把 edge boil 当成了完整绘画动画。

这轮沿 `Puppet.instances → state.frames → hand → m/t` 追踪，并对照用户提供的 bio-showcase 源码。现在完整三稿会改变细微形体、颜料裁切、结构线与局部细节；关节/地面不漂移，连续动作保留。Studio 加入同姿态并排对照，验证必须同时看内部画稿差异和正常速度的生命感。迁移到 SaaS 时，应给折页、夹子或图例设计自己的画稿，业务字与固定结构保持可读；不要把这项研究再次收窄成增加角色数量。
